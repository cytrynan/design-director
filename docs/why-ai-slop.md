# なぜAIのUIは同じ顔になるのか（設計の根拠）

このプラグインが「方向性の強制選択」「トークン固定」「ブラックリスト」という
3点セットで構成されている理由をまとめる。

## 原因: 分布収束

AIが生成するUIが似るのは能力不足ではなく **分布収束** が原因。
指示が無いとモデルは学習データの統計的平均（＝最も安全で無難な見た目）を出力する。

そのため **「もっと良くして」「おしゃれにして」は効かない**。
平均から離れる方向が指定されていないので、何度言い直しても平均に戻る。

対策は次の3つに集約される。

1. 方向性を**1つ強制選択**させる（平均から離れる方向を固定する）
2. トークンを**具体値で固定**する（画面ごとのブレ＝平均への回帰を防ぐ）
3. AIの既定値を**ブラックリストで封じる**（ネガティブ制約）

## 効く施策（効果が大きい順）

1. **タイポグラフィ交換** — Inter / Roboto / Poppins / Space Grotesk / Geist をやめるだけで印象が最も変わる。
   和文も Noto Sans JP 一択にしない（Zen Kaku Gothic New / BIZ UDPGothic / Shippori Mincho 等）。
2. **レイアウト構造ごと変える** — 色やボタンだけ差し替えても「標準SaaSヒーロー構造」のままでは見抜かれる。
   エディトリアル型（1カラム長文・引用・図版インライン）など、構造から選ぶ。
3. **DESIGN.md にトークンを固定** — 方向性・配色(60/30/10)・フォントペア・角丸/影・8pt余白・モーションを
   プロジェクトルートに記録し、全画面の単一の正とする。
4. **ブラックリスト照合** — 紫グラデ / 中央ヒーロー+badge / 3枚カード / 1px灰枠カード / 色付き左ボーダー /
   一律fade-in / 理由なきダーク+ネオン等の「指紋」をQAで機械的に弾く。

## 可読性ガードレール（個性より優先）

方向性に関わらず常時ON:

- 本文16px以上
- 行長60〜80字
- 十分なコントラスト（WCAG AA目安、可能ならAPCA Lc75/45/30）
- タップ領域44px以上
- 階層はサイズと太さで明示

**「個性的だが読みにくい」は不合格。** 迷ったら可読性を取る。

## 公式 `frontend-design` スキルとの関係

Anthropic公式プラグインの `frontend-design` スキルも同趣旨。
本プラグインはその**強化・具体化版**という位置づけで、方向性メニュー6種・
和文フォント指定・DESIGN.md によるプロジェクト横断の一貫性維持を足している。
併用しても矛盾しない。
